# ADR-006. Агент добавляется манифестом, а не правкой четырёх мест

Дата: 2026-11-16. Статус: принято.

## Контекст

До 15.11.2026 инфраструктура была привязана к конкретным агентам: скиллы раздавались
junction'ами из `_agent\skills\` в `~\.agents\skills` (OpenCode), субагенты синкались
скриптом в Grok и OpenCode отдельными путями, MCP-конфиг регенерировался в два формата,
команды линковались в `~\.config\opencode\command`. Каждый новый агент требовал правки
в четырёх местах и запоминания путей.

После сбоя выяснилось, что восстановить эту схему нельзя: ни один из путей не был описан
в одном месте, а самих агентов (Grok, Hermes, ZCode) больше нет.

При этом агенты будут добавляться и дальше — это не разовая задача.

## Решение

Каждый агент описывается **манифестом** `_agent\agents\<id>.json`:

```json
{
  "id": "opencode",
  "enabled": true,
  "skills_dir": "~/.agents/skills",
  "subagents_dir": "~/.config/opencode/agents",
  "commands_dir": "~/.config/opencode/command",
  "mcp_config": "~/.config/opencode/opencode.json",
  "mcp_format": "opencode"
}
```

`scripts\sync-agents.ps1` читает все манифесты и применяет канон: junction'ы скиллов,
копии субагентов, команды; `scripts\mcp-sync.ps1` переносит MCP-реестр в конфиг агента.

**Добавление агента = новый json + `sync-agents.ps1`.** Правок в `skills-src`, `subagents-src`
и `mcp` не требуется.

## Почему так, а не «просто дописать ещё один путь в скрипт»

1. **Один источник правды.** Список агентов и их путей — данные, а не код. Видно глазами,
   диффится в git, не требует помнить имена каталогов.
2. **Скиллы не дублируются.** Канон один, агенты получают junction'ы. Новый агент сразу
   видит все скиллы и не тянет вторую копию.
3. **Честная деградация.** У агента без каталога скиллов (DSH — подключает плагинами)
   в манифесте `skills_dir: null`, и sync просто сообщает об этом. Никакой магии.
4. **Проверяемость.** `doctor.ps1` читает те же манифесты и говорит, у кого какие скиллы
   реально привязаны и что сломано.

## Следствия

- Формат субагента фиксирован: `agent.md` с frontmatter (`name`, `description`, `mode`,
  `model`, `tools`, `permission`). Если агент требует другого формата — это отдельный
  конвертер в `sync-agents.ps1`, а не второй набор исходников.
- `skills_dir: null` — легальное состояние, фиксируется в `docs\state-of-workspace.md`.
- MCP пишется только с `-ApplyMcp` / `-Apply`: конфиги агентов — пользовательские данные,
  молча их менять нельзя (делается `.bak`).
- Существующий настоящий каталог на месте junction'а не удаляется: скрипт предупреждает.
  Это правило появилось после того, как старый bootstrap стирал каталог без вопросов.

## Что не решено

- Для DSH MCP-формат (`cordis.yml`) не реализован: сначала нужно понять, как профиль
  подключает плагины, потом писать конвертер. Пока `mcp_format: cordis` — заглушка.
  Каталог скиллов у DSH тот же, что у OpenCode (`~/.agents/skills`), субагенты и команды
  задаются пресетами, а не плоскими файлами.
- Нет версионирования манифестов: если у агента поменяется формат скиллов, старый json
  станет неверным молча. Лечится полем `schema` в манифесте, когда появится второй формат.
