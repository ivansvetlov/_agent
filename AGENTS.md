## 1. Что это за место

Один рабочий корень, внутри — только работа. Конфиги агентов живут в профиле (`~\.dsh`,
`~\.config\opencode`), а не здесь: инструменты сами знают, где им быть.

```
Workspace\
├── AGENTS.md          ← этот файл: правила для всех агентов
├── README.md
├── projects\          ← только git-репозитории, каталог = имя репо
├── _agent\            ← этот репозиторий: конституция, скиллы, субагенты, MCP, шаблоны, инструменты
├── _notes\            ← заметки вне кода: разборы, замыслы, экспорты
├── _inbox\            ← «разберу потом» (в gitignore)
├── _archive\          ← старьё, архивы сессий агентов
└── _backup\           ← манифесты и скрипты бэкапа
```

Служебное помечено `_`. Всё, что не `_` и не `projects\*`, — либо конституция, либо мусор.

## 2. Правила (обязательны для всех агентов)

1. **Всё в git — с remote.** Репозиторий без remote считается незащищённым: при сбое он исчезнет
   целиком. Так уже случилось с `_agent` 15.11.2026 — восстановили 11 файлов из 17.
2. **`docs\HANDOFF.md` в каждом проекте.** Обновляется в конце сессии: что сделано, что дальше,
   где развилки. Это единственный файл, по которому работа продолжается с нуля.
3. **Один проект = один репозиторий.** Каталог называется как репозиторий: латиница, строчные,
   дефисы. Воркспейс репозиторием не становится.
4. **Перед удалением или перезаписью — посмотри на цель.** Не твоё, не совпадает с описанием —
   стоп, спроси.
5. **Секреты — только в `.env`** (в gitignore). В git — `.env.example`. Токены не выводить в лог.
6. **Evidence-first.** «Работает» без теста, скриншота или команды — не аргумент.
7. **Не угадывай проект.** Живые репозитории перечислены в §3; сомневаешься — спроси.
8. **Пиши как окружающий код.** Именование, плотность комментариев, идиомы — как в файле рядом.
9. **Необратимое — с подтверждением.** Пуш в чужой репо, деплой, удаление данных, `git push -f`.
10. **Зависимости — в проект.** `.venv\`, `node_modules\` внутри проекта; глобальные установки —
    только по явной просьбе.
11. **Не мусори в корень.** Одноразовое — `scripts\_scratch\`, «разберу потом» — `_inbox\`.
12. **Кириллица — только в содержимом.** Пути, имена файлов, слаги — латиница.

## 4. Как добавить агента

Агенты не «настраиваются вручную в четырёх местах», а подключаются манифестом.

`_agent\agents\<id>.json` описывает, куда агенту класть канон:

```json
{
  "id": "opencode",
  "name": "OpenCode",
  "enabled": true,
  "skills_dir": "~/.agents/skills",
  "subagents_dir": "~/.config/opencode/agents",
  "commands_dir": "~/.config/opencode/command",
  "mcp_config": "~/.config/opencode/opencode.json",
  "mcp_format": "opencode"
}
```

Дальше `scripts\sync-agents.ps1`:

- копирует каждый каталог из `skills-src\` в `skills_dir` агента и ставит маркер `.canon-hash`
  (по нему потом видно, что копия своя и не разъехалась; junction-режим остался как `-Mode junction`);
- раскладывает `subagents-src\<name>\agent.md` в `subagents_dir` (с учётом формата агента);
- копирует `commands\` в `commands_dir`;
- показывает diff по MCP-конфигу (и применяет только с `-ApplyMcp`).

**Новый агент = новый json + запуск sync.** Никаких правок в skills-src, никаких «вторых копий».
Если у агента нет каталога скиллов, в манифесте `skills_dir: null` и скиллы ставятся его штатным
способом (у DSH это тот же `~/.agents/skills`, у остальных уточняется на месте); это фиксируется
в `docs\state-of-workspace.md`.

## 5. Скиллы, субагенты, MCP

| Что | Канон | Куда попадает |
|---|---|---|
| Скиллы | `skills-src\<name>\SKILL.md` | копии в `skills_dir` каждого агента (маркер `.canon-hash`) |
| Субагенты | `subagents-src\<name>\agent.md` | `subagents_dir` (frontmatter + тело промпта) |
| MCP | `mcp\mcp-servers.json` | конфиг агента, через `scripts\mcp-sync.ps1` |
| Команды | `commands\<agent>\<name>.md` | `commands_dir` |

Править **только канон**. Копии в каталогах агентов — производные: `doctor` покажет расхождение
(DRIFT), а `sync-agents.ps1` перезапишет.

## 6. Новый проект

`scripts\new-project.ps1 -Name foo -Kind static|service` — создаёт каталог из `templates\project\`,
инициализирует git, подставляет имена. Дальше: `git remote add`, первый коммит, `docs\HANDOFF.md`
с первой записью.

Скелет проекта: `README.md` (первая строка — статус), `AGENTS.md`, `docs\{ARCHITECTURE,DECISIONS,HANDOFF}.md`,
`scripts\`, `tests\`, `data\` + вариант: `site\`/`prototype\` (статика) или `app\`/`web\`/`deploy\`/`out\` (сервис).

## 7. Git

- `main` по умолчанию; `master` — только у `bloom-crm` (исторически).
- Conventional commits: `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
- Перед пушем: `git status` чист, `git fsck` без ошибок, `docs\HANDOFF.md` обновлён.
- Кириллица в путях ломает CI и часть тулинга: `core.quotepath=false` включён глобально,
  но имена всё равно латиницей.
