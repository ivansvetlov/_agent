# Evidence-first

## Правило

Утверждение о результате допустимо только вместе с доказательством, которое можно повторить.
«Должно работать» не считается: либо проверка выполнена, либо так и говорится — «не проверял».

## Что годится как доказательство

| Тип изменения | Минимальное доказательство |
|---|---|
| Код на Python | `python -m py_compile` или запуск теста; тест падал до — прошёл после |
| JS/TS | `node --check`, `tsc --noEmit`, прогон теста |
| HTML/CSS | открытие страницы, скриншот или описание того, что видно; для интерактива — клик и результат |
| Скрипт PowerShell | запуск на реальном пути, вывод команды |
| Данные/миграция | до/после: количество строк, контрольная сумма, выборка |
| Git-операция | `git status`, `git log --oneline -1`, `git fsck` |
| Восстановление файлов | синтаксическая проверка + эталонная строка из документации |

## Как формулировать

Плохо: «Исправил шов, теперь 5px».
Хорошо: «Зазор на паре Ставропольский×Красноярский: было 0.4 → стало 4.9 (замер `_measure_gap.mjs`,
вывод в логе). На всех 27 парах медиана 4.8, минимум 3.1 у тройника — это ожидаемо, см. HANDOFF».

Плохо: «Сайт работает».
Хорошо: «Страница открыта на `localhost:8080/index.html`, консоль без ошибок, `kp/index.json`
отдаётся 200 — проверял fetch из консоли».

## Частые ловушки

1. **Подмена проверки рассуждением.** «Логика верная, значит работает» — не доказательство.
2. **Проверка не того.** Тест зелёный, но тестирует старую версию файла или другой регион.
3. **Отсутствие контроля.** Не показано, что до правки было плохо — возможно, ничего не изменилось.
4. **Скрытая зависимость от среды.** Работает в твоём каталоге, падает при запуске из корня.
5. **Частичная проверка.** Проверен один сценарий из трёх, а сказано «всё».

## Когда доказательства нет

Скажи прямо: «не проверял, вот что нужно, чтобы проверить» — и предложи однострочную команду.
Это лучше, чем уверенный тон без данных.
